# 관리자 초기 상태 구분 보완

> 최신 기준 안내(2026-11-22): 현재 v1.5.0은 SQLite 21개 테이블·141개 열, HTTP 34개 경로·36개 작업, 자동시험 87개 통과다. 아래의 기능 추가일·당시 시험 개수는 이력이다. 최신 [ERD](erd.svg)·[API 규격](API_SPEC.md)·[시험 기록](TEST_REPORT.md)을 함께 본다.

2026-11-18 · 백엔드 v1.4.1

## 무엇이 달라졌나

관리자 화면에서 ‘아직 판단 기록 없음’과 ‘기록이 있는 정상 상태’를 구분한다. 기존에는 둘 다 NORMAL이라는 이유로 정상 배지를 보여줬다.
GET /api/v1/admin/seniors의 각 items에 status_event_id를 추가했다. 개별 상태 API와 같은 DB 값을 반환한다.

| 응답 상태 | 관리자 화면 |
|---|---|
| status_event_id=null | 회색 ‘판단 기록 없음’, 상태 갱신 시각은 — |
| status_event_id가 있고 risk_level=NORMAL | ‘정상’과 상태 갱신 시각 |
| status_event_id가 있고 CAUTION 또는 DANGER | 기존 ‘주의’ 또는 ‘위험’과 상태 갱신 시각 |

장치 연결 수와 STALE/FRESH는 별도로 유지한다. 장치가 켜지거나 꺼졌다는 이유로 판단 기록을 만들지 않는다.
status_event_id 필드가 없는 옛 서버의 응답을 받으면 ‘판단 기록 확인 필요’와 서버 재시작 안내를 보여준다. 필드 누락을 초기 상태라고 단정하지 않는다.

## 확인하는 방법

1. 기존 서버 창에서 Ctrl+C로 끈다.
2. safehome-backend 폴더에서 start-admin-demo.cmd를 더블클릭한다. 또는 `.\.venv\Scripts\python.exe run.py`를 입력한다.
3. http://127.0.0.1:8000/admin-test 에서 Ctrl+Shift+R로 새로고침한다.
4. 판단 이벤트가 없는 대상은 ‘판단 기록 없음’으로 나온다. 기본 가상 데이터의 김안심·최빈목록이 해당하지만, 이미 시연한 대상은 기록이 있어 정상·주의·위험으로 나올 수 있다.
5. 기록이 없는 대상을 ‘시연 대상’에서 고른 뒤 ‘정상 시연’을 누른다. 해당 대상이 ‘정상’으로 바뀌고 갱신 시각이 나타나는지 확인한다.
6. ‘서버가 보내준 응답 보기’에서 해당 대상의 status_event_id가 null에서 이벤트 UUID로 바뀌었는지 볼 수 있다.

이번 보완을 확인하려고 기존 데이터를 초기화할 필요는 없다. 기존 개인 DB와 복약·사고 기록을 삭제하거나 덮어쓰지 않았다.

## 프론트 전달 규칙

새 필드: items[].status_event_id = UUID 문자열 또는 null. 응답에는 필드 자체가 항상 포함된다.
null이면 초기값 NORMAL을 AI가 판단한 정상으로 표시하지 않는다. risk_level의 기존 3단계와 저장값은 유지한다. UNKNOWN 등의 새 위험 단계를 추가한 것은 아니다.
last_updated_at도 호환을 위해 기존 값을 유지하지만, status_event_id=null일 때는 그 시각을 실제 판단 시각으로 보여주지 않는다.
기록이 있다는 것은 서버가 위험 판단 이벤트를 처리했다는 의미다. 현재 모의 서버의 이벤트나 취소 제스처 처리 후 NORMAL도 포함하므로 실제 AI 검증 완료·실제 안전 보장으로 표현하지 않는다.
frontend/schemas.ts, OpenAPI와 응답 예시도 함께 갱신한다. 기존 필드를 제거하거나 DB 테이블을 추가하지 않는다.
원본 프론트 기능명세서 COM-01·WEB-03의 초기 상태 구분 요구를 반영했다. 원본 XLSX는 수정하지 않았다.


## 완료 확인

전체 자동 시험 **64개 통과**, 실패 0개. 기존 63개와 초기 상태→정상 이벤트→장치 끊김/복구 후 판단 이벤트 유지 검증을 포함한다. TestClient 사용 중단 예정 경고 1건은 동일하다.
기존 관리자 조회 검사에서도 개별 상태 API와 status_event_id가 일치함을 확인했다. 최신 OpenAPI와 코드가 일치하며, 예시 34개 중 요청 본문 11개·응답 30개를 모델과 대조했다.
별도 메모리 DB의 실제 브라우저에서 김안심의 ‘판단 기록 없음’·갱신 시각 —를 확인했다. 정상 시연 후 ‘정상’과 이벤트 시각이 표시되고, 시연하지 않은 최빈목록은 계속 ‘판단 기록 없음’인 것을 확인했다.
새 화면 JavaScript 문법 검사도 통과했다. 기존 개인 DB를 초기화하지 않고 시험했다. DB 테이블·열은 기존 20개·137개를 유지한다.
