## 지금 바로 확인하는 순서

서버가 실행 중인 터미널에서 Ctrl+C를 누른다. safehome-backend 폴더에서 아래 명령을 입력한 뒤 검은 창을 열어 둔다.

```powershell
.\.venv\Scripts\python.exe run.py
```

브라우저에서 http://127.0.0.1:8000/admin-test 를 연다. 기존 첫 화면의 ‘관리자 전체 현황’ 링크로도 들어갈 수 있다. 이전 화면이 보이면 Ctrl+Shift+R로 새로고침한다.

1. ‘실시간 연결됨’ 문구를 확인한다.
2. ‘위험 시연’을 누른다. 선택한 어르신의 상태가 위험으로 바뀌고, 전체 사고 목록에 기록이 추가된다. 실시간 기록에도 경고가 나타난다.
3. 사고 목록의 ‘상세 보기’를 누른다. 발생 시각·위험 단계·설명·취소 제스처와 상세 응답을 볼 수 있다.
4. 사고 목록의 ‘대상’을 고르고 ‘사고 조회’를 눌러 대상별로 확인한다. 한국 시각 기준 시작·종료 시각으로도 조회할 수 있다.
5. ‘실시간 잠시 끊기’를 누른다. ‘주의 시연’을 누르고 ‘실시간 다시 연결’을 누른다. 끊긴 동안의 경고에 ‘다시 받은 기록’이 붙어 나타난다.
6. ‘장치 끊김 시연’과 ‘장치 복구 시연’을 누른다. 전체 현황의 연결 수와 실시간 기록이 바뀐다.
7. ‘패턴 변화 시연’을 누른다. 실시간 기록의 ‘기록 상세’에서 패턴 관찰 기간과 설명을 볼 수 있다.
8. ‘취소 기록 시연’은 새 취소 기록을 추가한다. 이전 사고 기록을 취소하는 버튼은 아니다.

연결이 끊겨도 같은 화면에서 자동으로 다시 연결을 시도한다. 직접 ‘실시간 잠시 끊기’를 눌렀다면 ‘실시간 다시 연결’을 눌러야 한다. 처음 접속할 때 서버가 꺼져 있었다면 서버를 켠 후 새로고침한다.
서버를 껐다 켜도 SQLite에 저장한 사고와 경고 기록은 유지된다. 화면의 최근 실시간 목록은 이번 화면에서 받은 최신 50개이며, 전체 사고 이력은 별도 사고 목록에서 확인한다.
브라우저 화면에서 한국 시각으로 표시하며 서버는 UTC 시각을 저장한다. 장치가 끊겨도 마지막 위험 상태와 갱신 시각을 유지한다.

## 새 API와 프론트 연결 규격

### 전체 사고 목록

GET /api/v1/admin/incidents

Authorization: Bearer <관리자 토큰>. 개발용으로 admin-demo-token을 사용할 수 있다. 비밀번호 로그인에서 발급된 관리자 세션도 가능하다.

| 요청 값 | 규칙 |
|---|---|
| page | 기본 1, 1 이상 |
| size | 기본 20, 1~100 |
| senior_id | 생략하면 전체. 등록된 어르신 UUID만 허용, 없는 대상은 404 |
| start_at | 선택. 시간대를 포함한 ISO 8601. 시작 포함 |
| end_at | 선택. 시간대를 포함한 ISO 8601. 종료 제외 |

start_at과 end_at이 모두 있으면 시작 < 종료여야 한다. 한국 시각 09:00은 `2026-11-17T09:00:00+09:00`처럼 전송하거나 UTC로 바꿔 보낸다.
응답은 items, page, size, total, total_pages다. 각 items는 기존 Incident에 senior_name을 추가한다: incident_id, event_id, senior_id, senior_name, event_time, risk_level, summary, status, created_at.
발생 시각 최신순, 같은 시각이면 incident_id 역순이다. 빈 목록은 items=[]이며 전체 0건이면 total_pages=0이다. 마지막 페이지를 넘어도 200과 빈 items를 반환하며 전체 건수는 유지한다.
OPEN/CANCELLED는 발생/취소 기록 상태다. 관리자 처리 완료나 확인 여부를 뜻하지 않는다. NORMAL 입력은 사고를 만들지 않는다.
상세는 기존 GET /api/v1/incidents/{incident_id}, 패턴은 GET /api/v1/patterns/{pattern_id}를 재사용한다.
미인증·만료 401, 비관리자 403, 잘못된 필터·페이지 422. 오류 JSON은 기존 형태를 유지한다.

### HTTP 경고 기록 복구

GET /api/v1/admin/sync?after_cursor=0&limit=100

관리자 전용. after_cursor는 기본 0, 0~9007199254740991의 정수. limit는 기본 100, 1~100.
응답은 events, next_cursor, latest_cursor, has_more다. 각 이벤트는 기존 FeedEvent에 senior_name을 추가하고 관리자용 4종류만 반환한다.
has_more=true면 next_cursor로 다음 묶음을 조회한다. false일 때 next_cursor는 허용 이벤트가 없는 구간도 통과한 전체 최신 순번이다. cursor는 연속 번호일 필요가 없다.

### 실시간 전체 경고

WS /ws/admin/live. HTTPS 배포 시 wss. 토큰은 URL에 넣지 않고 연결 후 10초 안에 첫 JSON 메시지로 전송한다.

```json
{"action":"SUBSCRIBE","access_token":"admin-demo-token","after_cursor":0}
```

after_cursor는 HTTP와 같은 범위의 정수다. 문자열·실수·음수·boolean은 거절한다. 구독 메시지의 미지정 항목은 거절한다.

| 서버 메시지 | 내용 |
|---|---|
| SUBSCRIBED | after_cursor, latest_cursor. 구독 확인과 연결 시점 최신 순번 |
| EVENT | cursor, event_id, senior_id, senior_name, event_type, occurred_at, data, replayed |
| CURSOR | cursor, has_more. 필터로 제외한 이벤트 구간을 포함한 처리 기준점 |
| PONG | timestamp. 클라이언트 PING 응답 |
| ERROR | error_code, message. 이후 연결 종료 |

허용 event_type: STATUS_CHANGED, INCIDENT_ALERT, DEVICE_STATUS_CHANGED, PATTERN_UPDATED. 복약 개인 알림·스피커 명령은 이 관리자 경고 채널에서 제외한다.
replayed=true는 연결 시점까지 이미 저장되어 있던 기록이다. 재연결 복구 기록을 새 사고 팝업으로 반복 표시하지 않도록 구분할 수 있다. 새 기록은 false다.
구독 후 클라이언트는 `{"action":"PING"}`을 보낼 수 있다. 그 외의 메시지는 거절한다. 예시 도우미와 확인 화면은 20초마다 PING을 보낸다.
종료 코드: 인증 실패·세션 종료 4401, 관리자 권한 없음 4403, 순번 기준 변경 4409, 잘못된 메시지 4400.
실제 로그아웃·만료뿐 아니라 연결 중 관리자 권한이 사라지는 경우에도 후속 관리자 전송을 허용하지 않는다.

### 초기 화면과 재연결 순서

처음 열 때: admin/sync의 latest_cursor를 먼저 저장 → 전체 현황·사고 목록 조회 → 저장한 latest_cursor를 after_cursor로 구독한다. 조회 중에 생긴 사건도 이후 재전송되므로 놓치지 않는다.
연결이 유지되는 동안: EVENT를 처리한 후 cursor를 저장한다. CURSOR도 저장하며 이미 처리한 순번 이하의 이벤트는 중복 표시하지 않는다. 이벤트 수신 시 현재 상태와 사고 목록을 다시 읽는다. 위험 상태를 오래된 재전송 이벤트만으로 덮어쓰지 않는다.
재연결: 처리한 마지막 cursor로 다시 SUBSCRIBE한다. 같은 DB로 서버가 재시작되어도 기록이 유지되므로 복구할 수 있다.
CURSOR_AHEAD / CURSOR_EXPIRED(HTTP 409 또는 WS ERROR+4409): 보관 중인 기준점이 유효하지 않다. 예전 순번을 지우고 위 초기 화면 절차대로 전체 재조회한다. 가상 데이터 초기화 전후의 값이나 다른 DB 백업으로 바뀐 경우 등이 해당한다.
순번은 서버 주소+관리자 계정별로 저장한다. 확인 화면은 개발용 관리자 한 계정의 같은 탭에 저장한다. 실제 프론트에서 계정을 바꾸면 이전 계정의 순번을 이어 쓰지 않는다.
이 UI는 자동 재연결을 1·2·4·8초 후 시도하고 이후 최대 15초 간격으로 반복한다. 인증 오류는 자동 반복하지 않는다.

frontend/api.ts 제공 함수: adminSeniors, adminIncidents, adminSync, subscribeAdmin. subscribeAdmin은 소켓 1개와 처리·순번·오류·종료 콜백을 제공한다. 실제 프론트는 onClose에서 마지막 순번으로 다시 호출하고 화면을 나갈 때 소켓을 닫는다. 확인 화면의 static/admin-operations.js에 재연결·복구 구현이 있다.
HTTP는 Swagger에서 실행해 볼 수 있으며 WS 실제 메시지 예시는 docs/admin-websocket-examples.json에 있다.

| 휴대폰 실제 푸시 | 프론트의 앱/기기 설정과 푸시 서비스 연결 정보 |
| 스피커 실제 안내 | 게이트웨이 명령 수신·실제 재생·결과 회신 |
| 외부 공개·실제 운영 | 배포 환경·HTTPS·실제 장치 인증·계정 운영 정책 |

현재 구현된 저장·조회·명령·모의 알림 흐름과 실제 기기 전달은 구분한다. 모의 센서 값이나 신뢰도는 실제 모델 정확도 검증 결과가 아니다. 최종 팀 규격 확정·프론트 연동 완료로 표현하지 않는다.
실제 휴대폰 푸시·실제 AI·스피커를 연결한 시험은 아직 하지 않았다. 와이파이가 끊겨도 로컬 서버는 동작하지만 다른 기기 접속·외부 서비스 및 Codex와의 대화 연결은 인터넷 상태에 영향을 받는다.


## 이번 검증 결과

전체 자동 시험 **63개 통과**, 실패 0개. 기존 45개와 전체 사고·실시간·복구 관련 18개를 포함한다. 기존 TestClient의 사용 중단 예정 경고 1건은 실패가 아니다.
임시 DB에서 전체/대상/기간 조회, 시작 포함·종료 제외·한국/UTC 변환, 동시각 정렬·페이지 경계·빈 목록·취소 기록, 관리자 외 차단을 검증했다.
실시간은 205개의 관리자 이벤트를 여러 묶음으로 재전송하고 개인 복약 이벤트를 제외하는지, 필터로 빠진 순번도 진행하는지, 구독 전후 사건·재연결·순번 오류·잘못된 메시지·PING/PONG·세션 만료·로그아웃·서버 재시작 후 기록 유지를 검증했다.
실제 브라우저의 별도 메모리 DB에서 위험 시연에 따른 상태·사고·경고 갱신, 사고 상세, 대상별 빈 목록, 잠시 끊기 후 경고 재전송, 장치 끊김·복구, 패턴 상세를 확인했다. 개인 PC의 기존 DB에 시연 사건을 추가하거나 기존 자료를 삭제하지 않았다.
최신 OpenAPI와 코드가 일치한다. HTTP 32개 경로·34개 요청/응답 예시 중 요청 본문 11개·응답 30개를 모델로 검증했다. 관리자 WS 메시지 예시는 별도 JSON으로 생성했다. JavaScript 문법 검사를 통과했다. 실제 프론트 앱·외부 네트워크·실제 AI·휴대폰 푸시·스피커 연동은 미검증이다.
DB 구조는 기존 20개 테이블·137개 열을 유지한다. 이번에 테이블을 추가하거나 저장 자료를 초기화하지 않았다.

## 파일로 확인하기

이 문서는 완료 내용과 노션 정리용으로 사용할 수 있다. HTTP 규격은 docs/openapi.json, 요청·응답은 docs/EXAMPLES.md와 docs/examples.json, 실시간 예시는 docs/admin-websocket-examples.json, 자동 검증 이력은 docs/TEST_REPORT.md다.
화면 증빙은 outputs/관리자_전체사고_상세확인_2026-11-17.jpg와 outputs/관리자_실시간경고_재연결확인_2026-11-17.jpg에 저장했다.
서버를 켜기 쉽게 start-admin-demo.cmd를 추가했다. 서버가 이미 실행 중이면 먼저 이전 창에서 Ctrl+C로 끈 뒤 이 파일을 더블클릭한다. check-backend.cmd를 더블클릭하면 설치된 환경에서 자동 시험을 다시 실행할 수 있다. 이 두 파일은 새 라이브러리를 내려받지 않는다.
