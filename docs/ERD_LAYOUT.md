# 2026-11-24 ERD 배치 정리

실제 SQL 스키마·API·테이블·필드는 변경하지 않고 그림 배치만 정리했다.

| 그림 | 표시 범위 | 읽는 방법 |
|---|---|---|
| [erd.svg](erd.svg) | 핵심 9개 표·9개 관계·주요 필드 | 발표용. 어르신 중심의 장치·사고·복약과 보호자 연결을 직각선으로 표시 |
| [erd-relationships.svg](erd-relationships.svg) | 전체 21개 표·PK/FK 53개 열·33개 FK | 각 FK 오른쪽 참조 상자에 목적지 표.PK를 표시 |
| [erd-detailed.svg](erd-detailed.svg) | 전체 21개 표·141개 열·33개 FK | 모든 필드와 관계를 같은 참조 상자 방식으로 확인 |

R01~R33은 그림에서 선을 구분하는 번호다. 실제 DB 컬럼이나 새 테이블이 아니다. 동일한 이름의 참조 상자는 같은 원본 테이블을 가리킨다. 긴 연결선을 화면 전체에 걸치지 않게 반복 표시했다.

숫자는 반대편 한 행과 연결되는 행 수다. 1은 한 개, 0..1은 없거나 한 개, 0..N은 없거나 여러 개다. 현재 그림의 실선은 필수 FK, 점선은 NULL 허용 FK다. 선은 데이터 처리 순서를 뜻하지 않는다.

예: medication_schedules.senior_id 오른쪽의 seniors.senior_id 참조 상자는 해당 일정이 어느 어르신에게 속하는지 연결한다. 같은 seniors 참조가 여러 곳에 나와도 어르신 표가 여러 개 생긴 것은 아니다.

drawDB JSON은 실제 21개 표와 33개 관계를 유지하고 표 좌표만 재배치했다. 발표는 핵심 ERD로 하고 전체 표 검토는 전체관계·전체필드 SVG를 확대한다. 기존 복잡한 그림은 history_2026-11-24/erd_before에 보관했다.
