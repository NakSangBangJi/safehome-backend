# 비밀번호 로그인 확인하는 법

> 최신 기준 안내(2026-11-22): 현재 v1.5.0은 SQLite 21개 테이블·141개 열, HTTP 34개 경로·36개 작업, 자동시험 87개 통과다. 아래의 기능 추가일·당시 시험 개수는 이력이다. 최신 [ERD](erd.svg)·[API 규격](API_SPEC.md)·[시험 기록](TEST_REPORT.md)을 함께 본다.

2026년 11월 17일 · API v1.2.0

## 1. 서버를 다시 켜기

서버가 실행 중인 터미널에서 Ctrl+C를 한 번 눌러 멈춥니다.
safehome-backend 폴더에서 아래 명령을 입력합니다.

```powershell
.\.venv\Scripts\python.exe start_login_test.py
```

터미널을 계속 열어 둡니다. 기존의 `python run.py`도 계속 사용할 수 있지만, 처음에는 위 명령이 연습용 비밀번호 파일까지 준비해 줍니다.

## 2. 계정 파일 열기

safehome-backend → data → login_demo_accounts.txt 파일을 엽니다.
guardian-demo는 보호자, senior-demo는 어르신 본인, admin-demo는 관리자입니다.
각 계정 밑의 비밀번호를 복사합니다. 이 파일은 내 PC의 연습용 파일이며 발표·팀 공유 자료에 넣지 않습니다.
기존에 비밀번호가 설정된 계정은 덮어쓰지 않습니다.

## 3. 로그인 화면 열기

브라우저 주소에 http://127.0.0.1:8000/login-test 를 입력합니다.
기존 첫 화면 위쪽의 ‘비밀번호 로그인 확인’을 눌러도 됩니다.

1. guardian-demo와 계정 파일의 비밀번호를 입력하고 ‘로그인’을 누릅니다.
2. ‘내 어르신 목록 보기’를 누릅니다. 3명이 나오면 보호자 조회가 됩니다.
3. 새로고침 후에도 보호자 이름이 남아 있는지 봅니다.
4. ‘로그아웃’을 누르고 ‘내 로그인 확인’을 누릅니다. 다시 로그인하라는 안내가 나옵니다.
5. senior-demo로 로그인한 뒤 목록을 보면 본인 1명만 나옵니다.
6. admin-demo로 로그인한 뒤 목록을 보면 전체 4명이 나옵니다.

비밀번호가 틀리면 로그인되지 않습니다. 같은 아이디로 5번 실패하면 최대 15분 동안 제한됩니다.
로그인은 1시간 후 만료됩니다. 만료도 서버에서 자동 검사합니다.

## 이번에 만든 것

| 기능 | 확인 위치 |
|---|---|
| 아이디·비밀번호 검사 | /login-test의 로그인 버튼 |
| 서버에 저장된 역할에 따른 조회 | 내 로그인 확인 / 내 어르신 목록 보기 |
| 새로고침 후 로그인 유지 | 로그인한 탭에서 새로고침 |
| 로그아웃 후 접근 차단 | 로그아웃 → 내 로그인 확인 |
| 서버 재시작 후에도 만료 전 로그인 유지 | 서버 재시작 후 같은 탭에서 내 로그인 확인 |
| 로그인 만료·연속 실패 제한 | 자동 시험으로 확인. 사용자가 시간을 기다릴 필요 없음 |
| API 문서 | /docs → 인증의 login / me / logout |
| 최신 DB 저장 형식 | /design/ → 데이터 사전 / SQL 스키마 |

기존 시연 화면의 역할 선택은 연습용 자동 로그인입니다. 비밀번호 로그인 확인 화면과 별개로 유지했습니다.
휴대폰 푸시·실제 AI·스피커 연동, 회원가입·비밀번호 재설정은 이번에 추가하지 않았습니다.

## 프론트 담당자에게 전달할 규격

POST /api/v1/auth/login : account_id와 password를 보내면 access_token, role, user_id, expires_in(3600초), expires_at, mock(false)을 받습니다.
화면에서 고른 역할로 권한을 주지 않습니다. 응답의 role이 서버가 정한 권한입니다.
보호 API에는 Authorization: Bearer <access_token>을 보냅니다.
GET /api/v1/auth/me : 현재 로그인 계정의 안전한 프로필만 반환합니다.
POST /api/v1/auth/logout : 본문 없이 보내며 성공은 204입니다. 그 토큰은 즉시 사용할 수 없습니다.
이미 연결된 /ws/live도 로그아웃·만료 후 종료됩니다. 401이면 로그인 화면으로 이동합니다.
프론트 도우미 frontend/api.ts에 passwordLogin, me, logout을 추가했습니다. 기존 login은 연습용 자동 로그인 메서드입니다.
기본 개발 모드에서는 기존 고정 토큰이 동작합니다. ENABLE_MOCK_AUTH=0으로 실행하면 사용자 고정 토큰과 mock-login이 차단됩니다. 장치용 시연 토큰은 별도이며 실제 배포용 장치 인증은 후속 작업입니다.

## 저장 방식과 시험 결과

비밀번호는 PBKDF2-HMAC-SHA256 600,000회와 계정별 무작위 salt를 적용한 검증값을 users.password_hash에 저장합니다.
로그인 열쇠 원문은 세션 DB에 저장하지 않고 SHA-256 검증값만 저장합니다.
auth_sessions(6열): 로그인 계정, 발급 시각, 만료 시각, 로그아웃 시각과 열쇠 검증값.
auth_login_attempts(3열): 해시 처리한 계정·접속 주소 단위 실패 횟수와 제한 기간 시작 시각.
로그인 추가 당시 DB는 18개에서 20개 테이블, 128개에서 137개 열로 확장했습니다. 이후 카메라 연결 표를 추가해 현재는 21개 테이블·141개 열이며, 2026-11-22 ERD도 이 구조에 맞췄습니다.
기존 복약 일정과 사건을 지우지 않고 테이블을 추가합니다. 가상 데이터 초기화는 기존처럼 시연 자료를 지우지만 연습 계정의 비밀번호는 유지하며 세션은 종료합니다.
한 프로세스의 로컬 개발 서버 기준으로 검증했습니다. 외부 서비스 공개, HTTPS와 실제 장치 인증 등은 후속 단계입니다.
